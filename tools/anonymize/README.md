# Анонимизатор XLSX/PDF для M&A DD

Локальный CLI. Маскирует российские реквизиты и PII в финдокументах **до** загрузки в Claude.

## Что детектится

**Regex (всегда):** ИНН (10/12), ОГРН (13/15), КПП, БИК, расчётный счёт (20), email, телефон РФ, организации по форме (`ООО Ромашка`, `АО ...`), ФИО по окончанию отчества (`-вич`, `-овна` и т.п. — ловит редкие фамилии которые natasha пропускает).

**Natasha NER (опционально):** русские ФИО (>=3 токенов), локации. ORG из natasha отключён — на финдокументах даёт массу false positives на балансовых заголовках. Требует `pip install natasha`. Короткие частотные слова (`ДА`, `НЕТ`, `РФ`, `ИТОГО` и т.п.) отфильтрованы блоклистом.

## Установка

Используется изолированный venv в `tools/anonymize/.venv/` (gitignored).

```powershell
# из корня репо, PowerShell
cd tools\anonymize
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активировать venv в текущей сессии (опционально):
```powershell
.venv\Scripts\Activate.ps1   # PowerShell
# или
.venv\Scripts\activate.bat   # cmd
```

Без активации — просто вызывай `.venv\Scripts\python.exe` напрямую (как в примерах ниже).

## Использование

```powershell
# Одиночный файл — mapping создаётся рядом (./mapping.json)
.venv\Scripts\python.exe anonymize.py report.xlsx

# Пакет от продавца — общий mapping на всю сделку
.venv\Scripts\python.exe anonymize.py ..\..\deals\target1\ `
    --mapping ..\..\deals\target1\mapping.json `
    --out-dir ..\..\deals\target1\anon\

# Review: посмотреть что найдено, не записывая файлы
.venv\Scripts\python.exe anonymize.py report.xlsx --review

# С переименованием файлов (анонимизирует и имена)
.venv\Scripts\python.exe anonymize.py ..\..\test-data\ --rename
```

### Флаг `--rename`

Без него: `Отчёт_ООО_Ромашка_2025.xlsx` → `Отчёт_ООО_Ромашка_2025.anon.xlsx` (название утекает).
С ним: имя файла прогоняется через тот же mapping, получится что-то вроде `Отчёт_ORG-001_2025.xlsx`. Маппинг старое→новое имя сохраняется в `mapping.json` под ключом `files`. Коллизии разрешаются суффиксом `-2`, `-3`.

## Как это работает

1. **XLSX**: openpyxl обходит ячейки. Строки заменяются, числа и формулы — нет (финданные остаются валидны). Имена листов и метаданные тоже чистятся. На больших книгах (>1M символов) natasha NER гонится чанками; при OOM авто-fallback на regex-only с WARN в лог.
2. **PDF (только текстовый)**: PyMuPDF (`fitz`) overlay — поверх оригинала. Для каждой сущности из mapping ищется bbox через `page.search_for()`, область редактируется (`add_redact_annot` + `apply_redactions` стирают текстовый слой), сверху впечатывается псевдоним тем же кеглем кириллическим TTF. **Вёрстка/таблицы/печати/чекбоксы сохраняются.** Длинные ключи обрабатываются первыми, короткие пересекающиеся bbox пропускаются (защита от наложений `ORG-001` поверх `TARGET-A`). После прохода — re-extract контроль: оставшиеся ключи логируются как `WARN: leak ...` без падения и без отката.
3. **Mapping**: один JSON на сделку. `ООО Ромашка → ORG-001` во всех файлах пакета консистентно. Хранится **локально**, в git не коммитится.

### Зависимости PDF
PyMuPDF (`pymupdf`) под AGPL. Для внутреннего DD-пайплайна это ОК. При внешней раздаче инструмента — рассмотри миграцию на `pdfplumber + pikepdf` или коммерческую лицензию PyMuPDF.

## Что НЕ делает (важно)

- Не обрабатывает сканы PDF (нет текстового слоя — нужен OCR, отдельная задача).
- Не работает с DOCX, PPTX, изображениями.
- Не детектит контекстные утечки («крупнейший аутсорсер в Новосибирске с выручкой 340 млн» — однозначно идентифицирует компанию даже без названия).
- На PDF с subset-шрифтами `page.search_for()` может пропустить слова — пропуски логируются как `WARN: leak ...`, проверь stderr после прогона.
- Многословные сущности с переносом строки могут пропускаться (PyMuPDF ищет точное вхождение). Лечится дополнительным проходом по словам — пока не реализовано.
- Natasha не идеальна на финансовом сленге; ORG из natasha отключён (см. выше), на больших книгах падает в OOM → авто-fallback на regex.

## Workflow для сделки

```
1. Создать папку: ./deals/target-2026-05/raw/   — сюда кладём оригиналы от продавца
2. Прогнать с --review, посмотреть mapping.json — глазами проверить детекты
3. Если нужно, добавить в mapping вручную пропущенные сущности
4. Прогнать без --review, получить ./deals/target-2026-05/anon/
5. В Claude грузить ТОЛЬКО ./anon/. mapping.json НИКОГДА не загружать.
6. После сделки — хранить mapping.json в защищённом месте (это ключ деанонимизации).
```

## Безопасность

- `mapping.json` и `raw/`, `deals/` добавлены в корневой `.gitignore`.
- Перед первой реальной сделкой — прогони на тестовом файле, посмотри `mapping.json`, убедись что детект адекватный.
- Для критичной чувствительности — используй Claude Enterprise с Zero Data Retention в дополнение к локальной анонимизации.
