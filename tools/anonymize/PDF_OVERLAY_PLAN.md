# План: PDF-анонимизация с сохранением лейаута (Фикс 2)

## Цель

Заменить текущий подход (`pdfplumber → reportlab` пересборка с потерей вёрстки) на **редакцию поверх оригинала** — псевдонимы появляются на месте оригинальных строк, остальная вёрстка (таблицы, шапки, печати, графики) остаётся как в исходнике.

## Текущее состояние (контекст)

- `handlers.py::process_pdf` извлекает текст постранично через `pdfplumber.extract_text()`, прогоняет через `mapping.apply()`, и пишет новый PDF через `reportlab` чистым моноширинным текстом без таблиц/картинок.
- Это работает для скармливания в Claude, но **нечитаемо человеком** — теряются таблицы баланса, ОПУ, шапки бухотчётности.

## Целевой результат

```
Оригинал:                          Анонимизированный:
┌─────────────────────┐            ┌─────────────────────┐
│ ИНФОТЕХ СЕРВИС, ООО │            │  TARGET-A           │
│ ИНН 5402553318      │     →      │  ИНН INN-001        │
│  [таблица баланса]  │            │  [таблица баланса]  │
│  [печать]           │            │  [печать]           │
└─────────────────────┘            └─────────────────────┘
```

## Подход (выбран после оценки 3 альтернатив)

**Hybrid: bbox-overlay через `pdfplumber` + `pikepdf`/`PyMuPDF`.**

1. Открыть оригинал.
2. На каждой странице получить **позиции слов** (`page.extract_words()` в pdfplumber даёт `text`, `x0`, `x1`, `top`, `bottom`, `fontname`, `size`).
3. Склеить слова в строки по `top` (с tolerance), найти в строке оригиналы из `mapping.entries`, посчитать bbox области для редакции.
4. На каждый матч:
   - Залить белый прямоугольник по bbox матча (через `PyMuPDF`/`fitz`: `page.add_redact_annot(rect)` + `page.apply_redactions()` — встроенная редакция, чистит ещё и текстовый слой под bbox).
   - Поверх вписать псевдоним — тем же шрифтом/размером, если кириллический шрифт доступен в PDF, иначе fallback на встроенный.
5. Сохранить как новый PDF.

### Почему PyMuPDF (`fitz`), а не pikepdf

- У PyMuPDF есть готовый `add_redact_annot` + `apply_redactions` — это **криптографически правильная редакция**: текстовый слой под прямоугольником стирается, не остаётся «невидимого» оригинала под белой заливкой.
- Через pikepdf пришлось бы вручную править content streams (PDF operators `Tj`/`TJ`/`BT`/`ET`) — сильно сложнее, ломается на subset-шрифтах.
- Лицензия PyMuPDF — AGPL. Для внутреннего использования в DD-пайплайне ИТЛ это ОК. Если позже понадобится коммерческая раздача — заменим на pdfplumber+pikepdf или купим коммерческую лицензию.

## Этапы реализации

### Этап 1 — Spike (1-2 часа)
- Поставить `pymupdf` в venv.
- Прототип: открыть один тестовый PDF из `test-data/`, найти все вхождения «ИНФОТЕХ СЕРВИС», нарисовать поверх белый прямоугольник и вписать «TARGET-A». Сохранить, открыть глазами.
- **Verify:** оригинальный текст исчез, лейаут сохранён, кириллица читается.
- **Если spike падает на кириллице/шрифтах** — переоценить подход, рассмотреть fallback (плоский overlay без замены текста, только маски).

### Этап 2 — Интеграция в handlers.py (2-3 часа)
- Заменить `process_pdf` на overlay-реализацию (flat-режим удаляется, fallback не предусмотрен).
- Использует mapping, который уже собран по тексту (как сейчас).
- Логика: открыть PDF → для каждой страницы найти bbox всех `mapping.entries` ключей через `page.search_for(text)` → редакция + вписать псевдоним.

### Этап 3 — Многословные сущности (1-2 часа)
- `page.search_for("ИНФОТЕХ СЕРВИС")` в PyMuPDF умеет искать многословные строки — работает из коробки.
- Но: если слова разнесены переносом или склеены с другим текстом — могут пропуститься. Логировать пропуски (WARN с указанием страницы и ключа).
- Контроль: после overlay-прохода прогнать `extract_text()` на результате, для каждого оставшегося ключа из `mapping.entries` писать WARN. Не падать, не откатываться — только лог.

### Этап 4 — Шрифты и кириллица (1 час, риск-зона)
- PyMuPDF умеет вставлять текст встроенными шрифтами (`helv`, `times`) — кириллицу они **не** поддерживают.
- Решение: подгружать TTF (`C:/Windows/Fonts/arial.ttf` или `consola.ttf`) через `page.insert_textbox(..., fontfile=...)`.
- Размер шрифта — взять из оригинального слова (`extract_words()` отдаёт `size`). Цвет — чёрный по умолчанию.
- Edge case: длина псевдонима ≠ длина оригинала. Если короче — норм. Если длиннее (например `ORG-001 TARGET-COMPANY-NAME`) — обрезать или уменьшать шрифт. Решить: при превышении ширины bbox выводить псевдоним с tooltip-меткой и логом.

### Этап 5 — Тесты (1 час)
- Прогнать на всех 6 PDF из `test-data/`.
- Открыть глазами 1-2 файла, проверить читаемость.
- Сравнить размер до/после.
- **Verify:** `extract_text()` на анонимизированном файле не содержит ни одного ключа из `mapping.entries`.

### Этап 6 — Обновить README + CLI help (15 мин)
- Отметить что flat-режим удалён, overlay — единственный путь для PDF.
- Зафиксировать known issues (см. ниже).

## Risks / Known issues

| Риск | Вероятность | Mitigation |
|---|---|---|
| PyMuPDF не справится со сканами в PDF (там нет текстового слоя) | Высокая для сканов | Текущая задача — только текстовые PDF, для сканов отдельный OCR-пайплайн |
| Subset-шрифты в оригинале → поиск по тексту не находит слова | Средняя | Fallback: после overlay-прохода прогнать text-extract проверку, при пропусках — flat-режим |
| Кириллический шрифт overlay-текста не совпадает с оригиналом → визуальный диссонанс | Высокая | Не критично для DD-документов (читаемость важнее перфекта) |
| Многословные сущности с переносом строки не находятся | Средняя | Доп. проход: искать слова по отдельности, если общая фраза не нашлась |
| Bbox от pdfplumber и от PyMuPDF могут не совпасть (разные координатные системы) | Низкая | Использовать ОДНУ библиотеку (PyMuPDF) и для поиска, и для редакции |
| AGPL лицензия PyMuPDF | Только при внешней раздаче | Сейчас инструмент внутренний — ОК. Если меняется — план миграции на pikepdf |

## Estimated effort

**~6-8 часов** один full pass до рабочего результата. Spike-этап (1-2 часа) первый — если на нём станет ясно что PyMuPDF не подходит, переоцениваем подход без большой потери.

## Решения (зафиксировано)

1. **AGPL PyMuPDF** — ОК, инструмент внутренний.
2. **Flat-режим** — удалить, fallback не нужен.
3. **Пропуски сущностей** — только лог (WARN), без ошибки и без отката.
